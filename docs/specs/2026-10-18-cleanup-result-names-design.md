# Issue #40 — 清理结果仅显示目录名称

用户要求简化“空演员目录清理结果”弹窗，并授权 Codex 实现、Kimi K3 唯一外门、版本 +0.0.1、exe 桌面交付和合并关闭 issue。本轮使用 [AFK](../../skill/afk/SKILL.md)，策略 `merge-when-green`；版本 **0.5.3**，不安装或部署。

## 方案

只改 `CleanupStatusBar` 结果弹窗：从本次任务 items 筛选 `status === "deleted"`，按现有顺序一行显示一个 name，保留长名称换行。移除弹窗内未删除项目、状态后缀、原因、完整 batch 路径、任务消息与会话说明；标题和关闭按钮保留。

没有已删除项时显示“暂无已清理的目录。”，按筛选后的数量判断，适用于零候选、全部保留、跳过、失败以及运行中尚未删除，不把“没有删除”误称为“batch 没有演员”。

弹窗外的任务状态、进度和统计继续显示，删除权限、后端任务、重试、互斥及列表刷新不变。同步项目现有版本锚点和 OpenAPI 的版本元数据，不修改 API 合同。

## 质询与验证

两轮只读质询均无阻塞：第一轮确认“清理的目录”指实际 deleted 项；第二轮确认空态必须依据 deleted 列表而非 total_count，失败／保留仍在全局统计可见。无需新框架或其他 UI 操作。

更新已有结果展示回归，覆盖混合结果只显示成功删除名称，弹窗外统计保留，以及零删除的真实空态；先验证旧界面不满足新断言，再最小修改。UI 类型、Biome、完整测试与构建，版本一致性及 Windows CI。代码自查两轮后提交、PR、CI → CTO → Kimi K3，按结果修复和交付。外门配额不足时如实记录降级。

所有服务启动或打包检查必须使用临时 FILMPAW_DB。此展示修复不执行真实片库删除测试。CI 成功产物核对 0.5.3 版本与 SHA-256 后复制桌面；合并后核对 issue 关闭并停止续跑进程。
